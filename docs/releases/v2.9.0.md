# csq v2.9.0

**Release date:** 2026-05-19
**Prior release:** v2.8.0 (2026-05-17)
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

---

## What's new

v2.9.0 makes **non-OAuth slots durable**. Before this release, slots authenticated by a third-party API key (MiniMax, DeepSeek, Ollama, Z.AI), by Codex, or by Gemini had no reliable record of _which identity owns the slot_ independent of the volatile `accounts` bookkeeping. The symptom users saw: `csq doctor` false-flagging healthy 3P/Codex/Gemini slots as "orphans," and slot identity at risk of being lost when stale `accounts` entries were pruned.

v2.9.0 introduces a dedicated **`by_slot_identity` recovery channel** that records each non-OAuth slot's identity in `profiles.json` at the moment it's established, so the slot is recoverable from its own durable record rather than inferred from terminal state. All three non-OAuth surfaces (3P API key, Codex, Gemini) now write this channel.

Bundled with it: `csq doctor` is now trustworthy on a healthy host. It reports **every** consistency issue at once instead of stopping at the first, and a stale internal check that produced phantom warnings has been retired — so a clean identity store now reports clean, and an inconsistency now means a real one worth investigating.

If you run csq with API-key or Codex/Gemini slots, this is the release where `csq doctor` stops crying wolf and slot identity stops depending on bookkeeping that can be pruned.

### What landed

#### `by_slot_identity` recovery channel for non-OAuth slots (PRs #500, #501, #504)

A new `by_slot_identity` map in `profiles.json` records the durable identity of every non-OAuth slot:

- **3P API-key + Codex slots (PR #500):** the channel and its daemon backfill/reconciler wiring. The daemon writes `by_slot_identity[N]` from the slot's own credential record; the live reader chain consults it (spec 02 §INV-07).
- **Gemini writer (PR #501):** Gemini is the 3rd and final non-OAuth surface to write the channel — `by_slot_identity` now covers 3P/Codex/Gemini uniformly.
- **Accounts-less 3P backfill arm (PR #504):** a slot whose only record is a 3P API key on disk (no `accounts` entry) is now correctly backfilled via a disk-walk arm, reclaiming slots the prior predicate left orphaned.

Net effect: `csq doctor` no longer false-flags non-OAuth slots, and the planned retirement of the legacy terminal-side `accounts` field will not orphan these slots.

#### `csq doctor` consistency reporting (PRs #505, #506)

- **All issues, not the first (PR #506):** `audit_coexistence` now returns a list of _every_ consistency issue (`--json` schema v8: `identity_store.consistency` is an array; empty = consistent). Previously it surfaced one issue per run, so fixing the first revealed the next only on re-run.
- **Retired stale `MirrorDriftAtSlot` check (PR #505):** the M3-7 credential mirror is inert in the current architecture; the check against it produced false "inconsistent" warnings on healthy hosts. Removed at root.

#### Account/slot identity hardening — RN1-C / RN1-D (PRs #484, #486–#496)

Internal correctness work for the account/slot decoupling effort (issue #292):

- Legacy numeric canonical writer + numeric reader fallback retired (RN1-C); `get_email` / reconciler paths fail closed instead of silently falling back.
- Identity label channel + rename migration; login captures a pre-existing rename label (RN1-D R2); accounts-prune closes the WINDOW-CLOSE gate gap (RN1-D R3, arm-3 mirrors `get_email` step 3).
- `update_email` is now serialized under `ProfilesFileLock` (RN1-A) — removes a profiles.json write race.
- `csq doctor` surfaces Pass-0 `oauth_email_unresolved` skips and unrecoverable post-relocation rename labels.

#### Documentation + process

Changelog backfill v2.7.6→v2.8.0; workspace closeouts for the by_slot_identity and non-oauth-slot-identity efforts; the WINDOW-CLOSE release-N+1 runbook gate; two repo-wide `/sweep` audits.

### Migration notes

- **No manual migration required.** Upgrading from v2.8.0 (or any v2.7.x/v2.8.x) is in-place. On first daemon start after upgrade, the reconciler backfills `by_slot_identity` for existing non-OAuth slots automatically — no user action.
- **`csq doctor` output changes:** `--json` `schema_version` is now `8`; `identity_store.consistency` is an array (empty = consistent) rather than a single field. Scripts parsing the old single-issue shape should read the array.
- **macOS auto-updater:** the v2.8.x → v2.9.0 transition is automatic. The build is Developer ID signed + notarized + stapled; the Tauri updater verifies the minisign signature against the same baked-in pubkey (`F1C2F7FD79F952DD`) used since v2.7.0 — trust chain unchanged. This release moves the auto-update pointer to `2.9.0`.

### What's not yet in v2.9.0

- **RN1-F (terminal `accounts`-field deletion)** — soak-gated by design (WINDOW-CLOSE N=2). The `by_slot_identity` channel shipped here is its prerequisite; RN1-F itself lands a later cycle.
- **CI-integrated macOS signing** — signing still runs on the maintainer box (`docs/release-signing.md`). Tracked; not blocking.
- **Intel Mac auto-update** — `latest.json::platforms` still only contains `darwin-aarch64`. Intel Mac users download `csq-desktop-macos.dmg` directly. Pre-existing gap, not regressed.
- **Windows EV cert** — Windows installers ship unsigned; SmartScreen shows the unrecognized-publisher prompt. Foundation does not currently hold an EV cert.
