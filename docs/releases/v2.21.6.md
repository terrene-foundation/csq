# csq v2.21.6

**Release preparation:** 2026-11-03
**Prior release:** v2.21.5.

Both editions ship this release: `csq` (community, Apache-2.0) and
`csq-ee` (enterprise edition, commercial licence). Items below apply to both unless a
section says otherwise.

---

## What's changed

### csq tells you when an account really needs a new login

csq used to mark an account as "login needed" after any failed token refresh, including
a passing provider hiccup or a local fault. A healthy account could then be refused by
`csq run`, or shown as needing sign-in on the desktop cards and in `csq status`.

Now only a refusal that really means "this grant is dead" sets the login-needed state. A
transient answer or a local problem leaves the account alone so the next attempt can heal
it. Marker files left by older versions are read safely: a marker csq cannot explain is
shown as "refresh failing, cause not recorded" instead of being treated as a login demand,
and `csq run` still launches the slot. `csq status`, `csq doctor` and the status line
report the two cases separately.

### Telegram owner bridge can now be set up, and csq can ping you

The Telegram bridge groundwork from v2.21.5 now has its setup commands:
`csq telegram setup`, `pair`, `on`, `off`, `status` and `rotate`. The bridge stays off
until you enrol and enable it. Pairing accepts only a private chat with you: group chats,
forwarded, edited or replayed messages, bots and stale messages are refused. The pairing
code lives only in memory for the five-minute handshake, and wrong guesses are counted
per chat, so a stranger cannot lock you out of pairing.

`csq notify-owner` sends you a one-line message through the paired bridge. The text is
read from standard input by default (so it does not appear in the process list or shell
history), is scrubbed of anything that looks like a credential before it leaves the
machine, is size-limited and refused rather than truncated when too long, and every ping
is recorded in the audit chain. The command prints only a fixed outcome, never the
message, chat or token.

### Windows: a path under a file is now refused, as on macOS and Linux

On Windows, reading a credential location whose parent folder had been replaced by a
regular file was treated as "nothing there", so a slot could look healthy when its
folder was broken. Windows now refuses it the same way macOS and Linux do, and the
same careful "missing versus unreadable" reading is applied across csq's file reads.

### Windows: unsupported command wrappers are refused before login starts

If the selected Codex, Gemini or similar tool on Windows is a `.cmd` or `.bat` wrapper,
csq now stops before any login side effect and tells you how to install a supported
executable, instead of failing partway through.

### Remote-control groundwork ships inactive

This release carries the first, authenticated and size-bounded control channel for
future remote session control: commands must be signed by the owner, are checked for
replay and expiry, and are tied to the local process that sent them. Stale sockets are
recovered only when csq owns them. Nothing in this release turns it on or exposes it,
and provider input is still refused, so existing sessions behave exactly as before.

## What's improved (developer-facing)

- **Sign-off and test reliability.** Tests that raced a departed client, an inherited
  listener or a forked child holding a lock now wait for the real condition. The
  desktop account-removal test reports its fixture state when it fails.
- **Preflight coverage.** Preflight reconciles with parked workflows, license-test
  discovery respects explicit parking, and freshness checks cover both parked and live
  registrations.
- **Windows census.** The Windows runtime read census is refreshed for the new sources.
- **Docs.** A broken public documentation link to an internal list was removed.
