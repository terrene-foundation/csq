# csq v2.21.5

**Release preparation:** 2026-11-02
**Prior release:** v2.21.4.

Both editions ship this release: `csq` (community, Apache-2.0, Terrene Foundation) and
`csq-ee` (enterprise edition, commercial licence). Items below apply to both unless a
section says otherwise.

---

## What's changed

### Move another running session to a different account

`csq swap <N> --session <NAME>` now rebinds a different live session to account `N`
instead of only the terminal you type it in. The name only selects which session to move;
the session's identity is never read from the name. An out-of-range slot is refused with
its own message. The same entry point is what a future remote control will call; it is
closed by default, so nothing outside the local command can use it yet.

### Telegram bridge groundwork ships switched off

This release carries the first building blocks of an owner-only Telegram bridge: its
configuration and secrets handling, the check that accepts messages only from the pinned
owner, the daemon intake, and the proof of where a message came from. All of it is inert.
There is no enrolment command in this release, the bridge configuration can only be
written by a local command that does not exist yet, and a bridge that is not enabled and
pinned to an owner accepts nothing. Nothing in this release contacts Telegram or changes
how an existing session behaves. Enabling it arrives in a later release.

### Windows desktop login keeps hold of its sign-in process

On Windows, the desktop app now starts each login vendor inside a private launcher placed
in a kill-on-close job, validates the handles before the vendor resumes, and reports a
login finished only after the original process has exited, its output readers are done
and the job is empty. Cancelling or quitting during a login keeps the sign-in process under
the app's control until it is proven gone, and a successful login is no longer reported as cancelled.

### macOS terminal launch no longer races on pseudo-terminal setup

Opening a session on macOS could race while the system prepared the pseudo-terminal.
That step is now serialised behind one guard with a two-second deadline, and a timeout
surfaces as a named `pty_grant_lock_timeout` error at the relay launch rather than a hang.

### Credential redaction covers more shapes

Redaction of credential-looking text now shares one bounded matcher for credential
context. It closes gaps around short numeric values and `Authorization` header
boundaries, keeps `Authorization` placeholders intact when a chat is resumed, and removes
the metadata key-name exemptions: only the explicit `public_TOKEN` name stays exempt, so
values next to keys such as `primary_key` and `sort_key` are masked again.

### A refused file replacement on Windows now says why

When Windows refuses to publish a file because the target is held or read-only, csq now
reports the cause in a fixed vocabulary, never a path, process id or content. A sharing
violation names the program holding the target, and an access-denied refusal names the
read-only attribute. The read-only hint no longer appears for a holder refusal.

### A failed restore never deletes the artifact it was restoring

When replacing a coc artifact failed and the restore of the prior copy also failed, the
partial-write cleanup could delete the artifact. The cleanup now preserves it, and the
restore contract is documented on `cleanup_partial_write`.

## What's improved (developer-facing)

- **Scoped push receipt.** The push guard accepts a scoped sign-off receipt and still fails
  closed for the categories that need the full set. Review closed a denylist that failed
  open on security paths, a rename that hid a security file, a receipt-chosen range and a
  gate-name newline that shifted the receipt protocol.
- **One isolated git-read helper.** The push guard and the commit hook read git through a
  single shared helper that scrubs the git environment (including the pathspec variables
  git documents as equivalents) and whose source marker cannot be forged from the
  environment or an exported marker.
- **Windows build and docs.** An unused import that broke the Windows lint leg is gated to
  Unix, and every broken intra-doc link, including platform-specific ones, now resolves.
  The Windows runtime census is refreshed for the changed read sites.
- **Test reliability.** The wedged-stub codex stop test no longer races its own descendant
  kill, the hook corpus-equivalence controls get the full validated time budget, a bridge
  token-leak test no longer races a Windows connection retry, and the messaging resolver
  guard recognises compound test-only `cfg` predicates.
