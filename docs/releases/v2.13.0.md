## What's new

**A++ CLOSEOUT.** v2.13.0 deletes the v1 `profiles.json::accounts` field that was deprecated in v2.10.0 (M4-9) and soaked for 6 minor versions (v2.6 → v2.12). an internal ticket is closed. The terminating WINDOW-CLOSE gate is satisfied: the RN1-D R3 reconciler pass (`prune_redundant_accounts_entries`, shipped v2.12.0) drained all recoverable populated `accounts` maps from every upgraded host on daemon start, so the `detect_v1_accounts_field` (`accounts.len() > 0`) predicate cannot fire on any v2.12.0+ host. The field is gone from the production struct; pre-M4-13 on-disk files load cleanly via the `#[serde(flatten)]` backward-compat hatch.

The 10-session / 23-milestone A++ identity-keyed storage roadmap (`internal-design-docs`) is formally terminated with this cut. The `identities/<UUID>/` subtree is csq's canonical per-account state; the v2.6.x downgrade window is closed; the always-on prune pass guarantees forward-cleanup on every upgraded host.

Auto-update propagates the new struct shape; existing hosts continue to load pre-M4-13 on-disk files without data loss via the `extra` hatch.

### Removed

#### `profiles.json::accounts` field deleted from `ProfilesFile` (an internal ticket, an internal ticket M4-13)

The `pub accounts: HashMap<String, AccountProfile>` struct field and the `pub struct AccountProfile` type are removed from production code in `csq-core/src/accounts/profiles.rs`. Pre-M4-13 on-disk files containing `accounts: {...}` are absorbed into `ProfilesFile::extra` via `#[serde(flatten)]`; the data is still accessible to reconciler passes through the new `legacy_accounts_email_map` helper. The `AccountProfile` struct and test helpers (`set_profile`, `accounts_for_test`) are retained under `#[cfg(any(test, feature = "test-utils"))]` for test fixtures that need to stage pre-M4-13 on-disk shapes.

### Changed

#### `get_email()` resolution order simplified (an internal ticket)

The former step (2) — `accounts[N].email` legacy compat — is removed. The method now resolves in two steps:

1. `by_slot_label[N]` (RN1-D2 label channel)
2. `by_slot_identity[N]` (RN1-D R3 non-OAuth identity channel)
3. `by_slot[N] → UUID → by_email`

Every slot that had an `accounts[N]` entry recoverable via another channel has had it pruned by the RN1-D R3 pass; genuinely unrecoverable entries were already holding the WINDOW-CLOSE gate open (correct behavior — they needed re-login).

### Added

#### Other shards in this cycle (PRs an internal ticket, an internal ticket)

- **`PrefsLock` typed newtype + `mutate_prefs()` helper** (an internal ticket, closes an internal ticket) — encapsulates the desktop-prefs read-mutate-write pattern under a typed lock. The `LoadOutcome` enum + `mutate_prefs` helper enforce that `load_desktop_prefs` + `save_desktop_prefs` are never called as a bare pair outside the helper; the `pub(in crate::desktop)` visibility structurally guards the invariant.
- **Corrupt-prefs disclosure banner** (an internal ticket, closes an internal ticket) — when `desktop-prefs.json` parses as malformed and is auto-recovered to defaults, the renderer now surfaces a one-time disclosure banner via the `consume_prefs_recovery` IPC command (take-and-clear semantics, 3 regression tests). 6 reason-tag log paths capture the corruption mode for support diagnosis.

### Internal

- **4 production callsites migrated.** `identity_mint.rs`, `doctor.rs`, and the `prune_redundant_accounts_entries` internal reader all updated to use `legacy_accounts_email_map`. Test-only callsites across 9 files updated to use `set_profile` / `accounts_for_test`.
