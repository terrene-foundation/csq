# csq v2.7.8

**Release date:** 2026-05-16
**Prior release:** v2.7.7 (2026-05-15)
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

---

## What's new

v2.7.8 is the **first stable release on the maintainer-signed macOS path**. The macOS DMG and auto-updater bundle are now Developer ID signed + Apple-notarized + stapled — first-launch on Sonoma+ works via double-click instead of right-click → Open, and Gatekeeper accepts the bundle offline. The Tauri auto-updater key (minisign `F1C2F7FD79F952DD`) is unchanged, so every existing v2.7.x install upgrades to v2.7.8 in-place.

Bundled with the signing work: `#292` Phase 4 self-heal automatically reconciles legacy `config-<N>/` layouts forward to UUID-keyed identities on daemon start, so users upgrading from any prior v2.7.x release don't need to run `csq doctor --repair-identities` manually.

If you've ever right-click → Open'd the csq DMG to bypass Gatekeeper, or held off upgrading because the macOS app reported "damaged or unsafe" on first launch, this is the release that fixes it.

### What landed

#### macOS Developer ID signing + notarization on stable tags (PR #466)

The Release workflow now classifies the pushed tag at the top of the run (`tag-classify` job). For stable tags (`vX.Y.Z`, no suffix), the `build-desktop` matrix skips its macOS cell entirely — the maintainer pre-uploads three macOS artifacts to the draft release before pushing the tag:

- `csq-desktop-macos.dmg` — Developer ID signed + notarized + stapled
- `csq-desktop-macos.app.tar.gz` — the auto-updater bundle (wrapping the SAME signed .app, per Gatekeeper's same-Team-ID-across-updates rule)
- `csq-desktop-macos.app.tar.gz.sig` — minisigned with the Tauri updater private key

The publish job's "Validate maintainer macOS artifacts" step is fail-closed: if any of the three are missing, the release does not ship. The maintainer flow is documented step-by-step at `docs/release-signing.md` § Local Signing + Notarization. Prerelease tags (`-rc.N`, `-alpha`, `-beta`) continue to use the in-CI ad-hoc-codesign fallback unchanged — only stable cuts go through the maintainer path.

This closes the v2.0.0 macOS-signing arc that originally landed as an ad-hoc workaround (Tauri's bundler left an incoherent .app signature; csq's `fix-dmg.sh` re-signed with `codesign --force --deep --sign -`). Ad-hoc signing was the right call when the Foundation had no Developer ID account; with the Apple Developer Program approval (2026-05-16), the proper signing chain is now live.

#### `csq doctor --repair-identities` + automatic Phase 4 self-heal (PRs #462, #463, #464)

The `#292` (account/slot decoupling) Phase 1 migration moves credential storage from `config-<N>/` (slot-keyed) to `identities/<UUID>/` (identity-keyed) so the same Claude/Codex/Gemini account can occupy different slots across machines and across daemon restarts. v2.7.7 shipped the Phase 1 storage layer; v2.7.8 ships the self-heal that runs on every daemon start for users upgrading from any v2.7.x release.

- **Automatic** (PR #462): the daemon startup reconciler (`csq-core/src/daemon/startup_reconciler.rs`) detects legacy `config-<N>/` layouts and reconciles them forward to UUID-keyed identities. Idempotent — re-running is a no-op once converged.
- **Manual** (PR #462): `csq doctor --repair-identities` exposes the same path for users who hit edge cases (e.g., a stale `.csq-account` marker pointing at a slot that no longer exists).
- **Codex parity** (PR #464): healed Codex identity files flip to `0o400` (read-only owner) to match the INV-P08 invariant the Claude path already enforced. Prevents accidental edits to managed identity files.
- **Diagnostic** (PR #463): `csq doctor` schema_version bumped from v4 to v5 with a top-level `phase-4-incomplete` alarm that surfaces when self-heal couldn't complete (e.g., permission errors on the identity directory). Catches the "upgrade silently skipped self-heal" failure mode where the daemon couldn't write but the user saw no error.

If you've never bound a Codex or Claude account, none of this affects you — the reconciler is a no-op on empty `accounts/` directories.

### Migration notes

- **No manual migration required.** Upgrading from v2.7.0–v2.7.7 to v2.7.8 is in-place: the daemon's Phase 4 self-heal runs on first start and converges the on-disk layout idempotently.
- **macOS users**: the auto-updater handles the v2.7.7 → v2.7.8 transition automatically. The new install is Developer ID signed, but Tauri's updater verifies the minisign signature against the same baked-in pubkey (`F1C2F7FD79F952DD`) the v2.7.x line has used since v2.7.0 — the updater trust chain is unaffected by the codesign-identity change.
- **If you previously right-click → Open'd the csq DMG**: nothing breaks. The Developer ID signature is additive; existing installs continue working.

### What's not yet in v2.7.8

- **CI-integrated macOS signing** (`docs/release-signing.md` § Future Work) — signing still runs on the maintainer's box. Moving it into GitHub Actions requires amending `rules/ci-real-oauth-prohibition.md` to allowlist the signing secrets (distinct threat class from user-OAuth secrets) plus a self-hosted macOS runner for signing reliability. Tracked for a future release; not blocking v2.7.8.
- **Intel Mac auto-update** — `latest.json::platforms` still only contains `darwin-aarch64`. Intel Mac users on v2.7.x must download the `csq-desktop-macos.dmg` directly. Pre-existing gap, not regressed by v2.7.8.
- **Windows EV cert** — Windows installers ship unsigned. SmartScreen continues to display the unrecognized-publisher prompt on first launch. Foundation does not currently hold an EV cert.
