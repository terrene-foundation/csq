# csq v2.21.1

**Release date:** 2026-10-22
**Prior release:** v2.20.2 (2026-10-03). v2.21.0 was tagged but never published; this release includes everything in the v2.21.0 notes.
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

---

## What's fixed

### The desktop app can no longer lose a background failure silently

A failure inside the desktop app's background work (its daemon supervisor, its anchor
sink, its cancellable operations) used to surface as a generic message, or in some
paths as nothing at all. Every one of those paths now routes through a single
fixed-vocabulary helper, so the app reports **which** piece failed in a stable,
recognisable form, and a panic in a worker is logged with the process it belongs to
instead of vanishing into a dead thread. The app also installs the daemon's redacting
panic hook at startup, so an unexpected panic is recorded without ever printing
credential material.

For anyone who has seen a desktop window disappear or a feature go quiet with no
explanation, this is the change that makes the next occurrence diagnosable.

### Windows file locking is no longer thread-confined

The Windows lock guard could be moved between threads and then fail to release — the
mutex stayed owned by the original thread until it exited, and every other process
waited. The guard is now marked as not safe to send across threads at compile time,
its release is checked rather than assumed, and the two places that genuinely needed
cross-thread locking were restructured to acquire and release on one thread. Linux and
macOS behaviour is unchanged.

### Releases can be published again

The v2.21.0 publish failed because some release steps ran `scripts/...` after changing
directory, so the path no longer resolved. Every such invocation in the release
workflow now uses a workspace-absolute path, and a new structural self-test reads the
workflow the way the shell would — steps, `cd`s, `working-directory:` and every
chunking spelling — so the same shape cannot be re-introduced silently. The
desktop IPC-buffer exception gate also now fails closed when it cannot verify how it
was invoked, instead of exiting 0 without checking.

### Dependency advisories

Three crates carrying new RustSec advisories are bumped, and the third-party
attribution bundles are regenerated for both editions.

## What's improved (developer-facing)

The local sign-off and CI test harness were hardened against false results: a per-test
watchdog now derives its budget from the enforced waits the code actually uses, fires
on **stalled progress** rather than a single test's age, kills the observed process
group rather than a bare pid, and reports exactly which test was running. A stopped
run can no longer report success. These changes remove a class of rotating CI failures
that were not product defects, so a red now means something.

## Upgrading

No command, configuration or on-disk format changed. `csq --version` reports `2.21.1`.
