# csq v2.11.0

**Release date:** 2026-05-25
**Prior release:** v2.10.1 (2026-05-23)
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

## What's new

v2.11.0 is the first stable cut that activates the in-bundle daemon garbage collection
end-to-end. Auto-update propagates the new daemon code to every csq user, clearing
accumulated `csq doctor` `INCONSISTENT` warnings and two of the three
`legacy_compat_state` bridges on the next desktop-app launch — no manual repair step
required.

### Fixed

#### Orphan-identity directory garbage collection (PR #551, issue context)

`csq logout`, `csq move`, and any other lifecycle event that drops the last reference to
an identity historically removed canonical credentials, the `config-N/` directory, and the
three profile-map entries — but left the `identities/<UUID>/` directory on disk.
`csq doctor` reported `Identity store: ⚠ INCONSISTENT: OrphanIdentity(<UUID>)` for every
accumulated orphan, and dead OAuth credentials lingered indefinitely.

v2.11.0 ships `prune_orphan_identities`, an idempotent, non-sentinel-gated reconciler pass
that deletes any `identities/<UUID>/` whose UUID is referenced by neither `by_slot` nor
`by_email`. The predicate has three whole-pass fail-closed guards (profiles unreadable,
both maps empty, store-version schema newer than this build) and a live-handle-dir scan
covering both the ClaudeCode `.credentials.json` and Codex `auth.json` symlinks — the GC
will never delete credentials a running terminal is reading.

Logout also gained a source-fix: when a logout drops the last reference to a UUID, it
removes the identity dir at the source. Map-removal is durably saved BEFORE the directory
delete, so a crash leaves an unreferenced (collectable) orphan, never a `by_slot` row
pointing at a deleted directory.

The convergence trail found and fixed a CRITICAL credential-deletion bug during the
in-session red team (the live-handle scan initially missed live Codex sessions because
Codex handle dirs symlink `auth.json`, not the guessed `.credentials-codex.json`). Both
fixes are pinned with regression tests.

#### Legacy credential mirror cleanup (PR #549)

M4-12 retired the writer to `credentials/<N>.json` (Anthropic) and `credentials/codex-<N>.json` (Codex) in v2.10.0, but left pre-M4-12 mirror files on disk. The `legacy_canonical_credentials_file` and `legacy_canonical_codex_credentials_file` detectors in `csq doctor` continued to fire, blocking the WINDOW-CLOSE P1 predicate.

v2.11.0 ships `prune_legacy_credential_mirrors`, the paired reconciler-cleanup half of the M4-12 retirement. It deletes mirror files whose identity-keyed successor at `identities/<UUID>/credentials.json` (or `credentials-codex.json`) exists and parses; otherwise it KEEPs them with a four-variant `KeptReason` taxonomy. Both `legacy_compat_state` bridges retire on this release; only `decimal_marker` remains (gated on a future product decision about pure-legacy install support).

### Added

#### macOS dock-icon-hide preference (PR #548)

New desktop option to hide the Code Squad Q dock icon and run as a menu-bar-only utility (NSApplication Accessory policy). Toggle persists in app preferences and takes effect on next launch.

### Internal

- **New rule `.claude/rules/reconciler-cleanup-parity.md`** (PR #553) capturing the 3-occurrence pattern (RN1-D R3 `prune_redundant_accounts_entries` + RN1-C R2 `prune_legacy_credential_mirrors` + orphan-GC `prune_orphan_identities`). Five MUST clauses governing future cleanup-pass authoring: writer/lifecycle retirement ships its paired cleanup in the same shard; deletion passes run after every reader; live-namespace passes hold the lock across snapshot+enumeration+deletion; scanners enumerate the producer's real on-disk names; predicates fail closed.
- **Spec 02 rev 1.17.0 → 1.18.0** adds `INV-ORPHAN-IDENTITY-GC` and a deviation log entry for the load-bearing lock-posture divergence from the RN1-C R2 sibling (this pass deletes in the live-mint namespace, so it must hold the profiles lock across the deletion to serialize against concurrent `csq login`).
- **Removed dead `sweep_orphan_identities`** (PR #551) — the sentinel-gated, warn-only sweep that was superseded by the GC pass. Its empty-maps guard is ported into the new pass.
- **23 net new tests** (16 GC unit incl. real-`mint_for_codex_login` Codex coverage + the `auth.json` regression test; 5 logout source-fix; 2 reconciler-wiring + doctor-consistency integration). Full workspace `cargo test`: **3178 passed / 0 failed**.

### Upgrade notes

Existing v2.7.x+ macOS installs receive v2.11.0 via the auto-updater. On first launch the
desktop app's new bundled daemon runs the reconciler chain, which prunes any accumulated
orphan identities and legacy credential mirrors silently — `csq doctor` should report
`Identity store: ✓ … consistent` after the first post-update launch, with
`legacy_compat_state` reduced from three bridges to one.

There is no manual repair step. Anyone who was running `csq doctor --repair-identities`
or similar can stop.
