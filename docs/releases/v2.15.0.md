# csq v2.15.0

**Release date:** 2026-06-07
**Prior release:** v2.14.0 (2026-05-27)
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

## What's new

Two things ship in this cut, accumulated on `main` since v2.14.0:

1. A **root-cause fix for an audit daemon lockout** that could brick the background daemon — the process that refreshes tokens and polls quota for **all** your sessions.
2. The **M12–M16 audit-trail governance build-out** (authority registry, pre-operation intent records, external anchoring, enterprise sinks, signed export cutoff).

**Most users only need the first part.** The audit-governance features are enterprise-/operator-facing and almost entirely **edition-gated or build-time feature-gated** — the default community build compiles none of the sinks and is otherwise unchanged. There is **no on-disk migration** and **no credential change**.

### Fixed

#### Daemon audit-brick — root-cause fix (PRs #659, #660, #661)

A lost-or-inaccessible audit signing key could put the daemon into a permanent `Broken` state, taking down token refresh and quota polling for every session. The real cause was **keychain inaccessibility, not key loss**: the non-interactive daemon cannot answer the macOS Keychain per-app-ACL prompt that fires when a binary's code signature changes across rebuilds, so it received `errSecInteractionNotAllowed (-25308)` — which the old code conflated with "key missing" and latched into a durable lockout.

The fix removes the interactive-keychain dependency from the daemon's availability-critical path:

- **File-mirror custody.** The audit signing seed now lives in a daemon-readable `0o600` file (`csq-runs/keys/<chain_id>/active.json`) that has no ACL and no prompt, so the daemon can always read it. This also restores durable audit-key custody on **Linux** (where the OS keychain backend was unavailable).
- **Keychain demoted to a non-fatal tamper detector.** The OS keychain is retained only as an integrity _anchor_ — surfaced on a new `csq doctor` **"Audit anchor:"** line (`Confirmed` / `Unconfirmed` / `Mismatch`). A disagreement is logged loudly but **never** fails the chain or bricks the daemon.
- **Verify decoupled from startup.** Audit-chain verification no longer runs in the daemon's startup-critical path; a broken or unverifiable chain degrades the audit subsystem only and can never take down refresh/poll. Access-failures route to a transient `Unknown` state (no durable `.chain-broken` sentinel); only a genuinely-absent current key stays fatal.
- **New recovery commands.** `csq audit migrate-keys` (interactive copy of a keychain-only key into the file store) and `csq audit repair [--apply]` (recover from a corrupt chain without losing sessions).

This fix is validated by five red-team rounds, a binary smoke test, and live deployment. See journals 0033–0035 and `specs/12-audit-trail.md` §12.11/§12.13 (v1.27.0).

### Added — Audit-trail governance (enterprise / operator-facing)

These extend the tamper-evident audit trail. Multi-signature and roster features are **edition-gated** (community builds are unaffected); the cloud sinks are **opt-in at build time** (default builds compile none of them).

#### M12 — Authority registry (an internal ticket)

Roster-enforced multi-sig membership, closing the Sybil gap where any self-signed key could inflate an approval count. A cryptographically valid signature from a **non-enrolled** key no longer counts toward a multi-sig threshold, and roster membership is role-scoped (a key authorized for `KeyRotate` can't approve `ReleaseAuth`). New `csq audit roster-install` / `csq audit roster-show`. Pre-roster records are grandfathered at install time. _Roster install requires the daemon stopped; the org-root signing key is operator-supplied, never baked in._

#### M13 — Pre-operation intent records (an internal ticket)

Append-FIRST intent: credential-mutating operations now record _"about to do X, authorized by Y"_ on-chain **before** the side effect runs, so a crash leaves an auditable "intent without outcome" instead of a silent gap. `csq doctor` surfaces any orphan intents (and a count). Also fixes a latent bug where key-rotation records were signed before sequence assignment (chain verification past seq 0 now holds).

#### M13b — Slot-lifecycle audit (an internal ticket)

Account **swap / logout / move-slot** now emit append-FIRST INTENT/OUTCOME records with shared correlation IDs — closing the gap where account-credential changes weren't auditable. Adds a 5-second lock-timeout on record writes (fail-safe when signing keys are unavailable) and redacts file paths from audit error messages.

#### M14 — External anchoring (an internal ticket)

The daemon can anchor audit-chain snapshots to an external witness (Rekor / csq-ledger), bounding the back-dating window: once anchored at sequence N, any retroactive insertion before N is structurally detectable even if the local chain is deleted. Failures are visible-but-non-fatal (surfaced in `csq doctor`, retried next tick). _Default config is local-only (`sink=none`); external submission is an operator opt-in._

#### M15 — Tier-2 enterprise sinks (PRs #654, #655)

Adds **AzureSqlLedgerSink** (database-tier append-only ledger tables), completing the four Tier-2 WORM/ledger reference sinks (S3 Object Lock, Azure Immutable Blob, GCP Bucket Lock, Azure SQL Ledger), now all covered by a dedicated `sink-conformance` CI job. _All sinks are feature-gated and ship with in-memory mock substrates; production use requires wiring the real cloud SDK per the per-sink operator guide (`docs/audit-sinks/`). Default builds compile none of them._

#### M16 — Signed export cutoff (an internal ticket)

`csq audit export` now embeds a signed **`CUTOFF.json`** carrying the chain HEAD snapshot, so an independent auditor can detect tail-truncation and confirm the export is anchored to the chain's head. The embedded `verify.py` gains explicit truncation detection and cross-checks against the external anchor when present.

### Internal / Developer

#### Build + CI (PRs #649, #655)

- `scripts/dev-install.sh` Developer-ID-signs the local CLI on install, eliminating recurring macOS keychain prompts across rebuilds (contributors without the cert fall back to ad-hoc signing).
- The new `sink-conformance` CI job tests all sink features on every PR, closing a coverage gap where sink code was only exercised locally.

### Upgrade notes

- **All users:** the daemon brick fix takes effect on this release. No action required, no migration, no credential change.
- **Existing audit chains:** if you have an audit signing key that exists only in the Keychain (no file copy), run `csq audit migrate-keys` once to copy it into the daemon-readable file store. Additive and reversible.
- **Security note (file-mirror custody):** the audit signing seed is now in a `0o600` file readable by any process running as your user, rather than behind a Keychain per-app ACL. This matches how csq already stores OAuth credentials and is strictly less sensitive than them; the Keychain is retained as a tamper detector (`csq doctor` → "Audit anchor:"). See `specs/12-audit-trail.md` §12.11.3a for the threat-model rationale.
- **macOS auto-updater trust chain unchanged** — Developer ID signed + notarized + stapled; minisign pubkey `F1C2F7FD79F952DD` (since v2.7.0).
- **Apple Silicon & Intel desktop users:** auto-update from v2.14.0 propagates this cut. **CLI users:** existing install methods unchanged.
