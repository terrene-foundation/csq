# S3 Object Lock Sink Operator Guide

**Feature flag:** `--features s3-sink`
**Sink name:** `s3`
**Target:** AWS S3 bucket with Object Lock in compliance mode

## Overview

AWS S3 Object Lock in compliance mode prevents deletion or overwriting of objects for the configured retention period, even by the bucket owner. Combined with versioning, it provides WORM (Write Once Read Many) storage suitable for audit anchoring.

## Enabling

```bash
cargo build --release -p csq --features cli,s3-sink --no-default-features
csq audit config-sink s3
csq audit config-cadence s3 cadence 1d
```

## Bucket prerequisites

1. Enable versioning on the S3 bucket.
2. Enable Object Lock (must be done at bucket creation time — cannot be added later).
3. Set a default retention policy in compliance mode:
   ```bash
   aws s3api put-object-lock-configuration \
     --bucket <bucket> \
     --object-lock-configuration '{
       "ObjectLockEnabled": "Enabled",
       "Rule": {
         "DefaultRetention": { "Mode": "COMPLIANCE", "Years": 7 }
       }
     }'
   ```

## IAM policy minimum

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:GetObjectVersion"],
      "Resource": "arn:aws:s3:::<bucket>/*"
    }
  ]
}
```

## Object key scheme

`<chain_id>/<record_id>.json`

## Production SDK integration

1. Add `aws-sdk-s3 = { version = "1", optional = true }` under `rekor-sink` → `s3-sink`.
2. Replace the in-memory store in `S3ObjectLockSink` with a `aws_sdk_s3::Client`.
3. Wire `append` → `put_object`, `verify_at` → `get_object`.

## Sink failure posture

Default: non-blocking. Failures queue to `.pending-s3/`. Override: `csq audit config-cadence s3 fail-loud true`.
