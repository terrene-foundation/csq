# csq v2.21.7

**Release preparation:** 2026-11-05
**Prior release:** v2.21.6.

Both editions ship this release: `csq` (community, Apache-2.0) and
`csq-ee` (enterprise edition, commercial licence). Items below apply to both unless a
section says otherwise. This release combines two development batches into one version.

---

## What's changed

### Automatic account rotation is now controllable per machine and per session

`csq rotation status|on|off|set` shows and changes the daemon's automatic account
rotation. A single live session can also be given its own auto-swap override, from the
CLI and from a new control in the desktop Sessions tab, and the desktop settings popover
has an auto-swap toggle. A rotation configuration csq cannot read is now reported and
refused instead of silently falling back to defaults, and the writers take a lock so two
changes cannot overwrite each other.

### Supervised session recycle

`csq session recycle` and `csq session memory` let csq restart a supervised session at a
safe turn boundary. Recycling is tied to the session csq started, waits for positive
evidence that a turn has ended, runs its gates before anything is stopped, and writes a
corrective audit record if the relaunch fails. Status line and `csq doctor` rows show
the supervision state.

### Telegram ping when an account needs a new login

When an account newly becomes login-needed, the daemon can send one combined ping to the
paired Telegram bridge. Alerts have a cool-off, nothing is sent for state csq cannot
trust, and an alert that was not delivered does not start a cool-off. `csq doctor`
reports a login-alert state file the daemon cannot read.

### Launches check what they are about to run

Every `csq run` launch of a coding-agent CLI now records a launch receipt: the
environment is scrubbed of credential names, manifests are checked, and sandbox
arguments that could contradict the recorded permission mode are refused. Refused
launches now end their audit record on every exit before the process starts.

### Audit records stay honest when a hand-off returns

If a Gemini hand-off returns instead of replacing the process, csq now writes a
corrective audit record on every platform, and restores normal pipe-closing behaviour
for the shell afterwards.

### Smaller improvements

- API-pool reset days 29 to 31 are accepted and clamp to the month's last day.
- The desktop keychain indicator uses plain language with a bounded details popover.
- The desktop shows a fresher backend value instead of a stale stored rotation setting.
- Relay groundwork (still inactive) gained audited writes bound to the live owner, a
  closed catalog for retained fixture evidence, and closed-socket detection on macOS.

---

## What's improved (developer-facing)

- **Community sync.** `scripts/sync-community.sh` removes build trees on exit, with a
  `--keep-build` opt-out, and refuses a work directory outside its guard.
- **Preflight.** Leg fan-out is capped per host, each leg's target directory is
  cleaned, and refusals name their cause.
- **Test reliability.** Load-sensitive tests tolerate a slow sign-off host, and the
  Windows change detector is skipped on manual runs.
