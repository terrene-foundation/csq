# csq v2.21.3

**Release preparation:** 2026-10-27
**Prior release:** v2.21.2.

---

## What's changed

### Safer credential diagnostics and response excerpts

HTTP error bodies are redacted before truncation, so cutting an excerpt does not leave
an otherwise recognized token fragment at the boundary. Excerpts and masked credential
displays use character boundaries. Short token and key displays are fully masked;
longer masked displays leave at least 16 characters hidden.

Key validation and the MiniMax and Z.AI bearer probes scrub submitted key material
before formatting response excerpts, including supported dotted segments and truncated
prefixes. Pattern redaction also recognizes more truncated `sk-` echoes and short,
digit-bearing credentials. `csq repair` reports refresh-token fingerprints instead of
raw token prefixes.

Shared HTTP helpers limit POST key-probe response bodies to 64 KiB and use a 1 MiB
default for other whole-body reads. Oversized bodies produce fixed messages without
response content; body-read errors use fixed phrases or the I/O error class. In
csq-ee, license revocation-list fetches have a separate 16 MiB limit and a distinct
`crl_too_large` diagnostic.

### Clearer sign-in failures

Claude and Codex login-grant failures identify the failed preparation or lease-writing
step and the operating-system error class/code. A refused grant creation is distinguished
from a quarantined login. Desktop quarantine messages use a location relative to the
accounts directory, and Claude desktop login errors also redact the home directory.
The CLI resolves the quarantine location for the operator's terminal while retaining
home-directory redaction.

### Completed messaging requests release their buffers

The MCP messaging server releases the previous request's buffer before waiting for the
next request, rather than retaining that allocation across idle waits.

### Dependency and advisory maintenance

The workspace moves to `dirs` 6, and desktop tooling updates include Tauri CLI, Vitest,
jsdom, and svelte-check. In csq-ee, advisory policy checks the reviewed RSA dependency
route on every invocation. The existing crypto-bigint exception is renewed through
2026-12-04 UTC; this is a policy exception, not an upstream vulnerability fix. Warnings
in blocking dependency-policy categories now cause refusal.

## What's improved (developer-facing)

Community extraction pins its source snapshot and checks preserved literals against
that same commit. Citation rewriting refuses unsupported contexts, and extraction
rejects an existing destination. Release workflows add workspace cleanup and checkout
safeguards, use hosted Linux and macOS build runners, and tighten the open-risk release
gate and job permissions.
