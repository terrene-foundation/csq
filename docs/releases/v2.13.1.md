## What's new

Patch release making `csq doctor` honest on healthy, fully-migrated hosts.

Two `csq doctor` diagnostics false-positived after the A++ identity-store migration completed:

- **`decimal_marker`** counted every `config-N/.csq-account` holding a decimal slot-id as a "legacy compat bridge pending migration" — including third-party API-key slots (MiniMax / DeepSeek / Ollama / Z.AI), which carry decimal ids **by design** (they use the `by_slot_identity` recovery channel and never receive a UUID), and modern OAuth slots whose marker simply never got rewritten by a login/swap.
- The **legacy-terminal count** flagged every `config-N` with credentials not bound to a live handle dir as a "legacy terminal" — flagging idle-but-migrated accounts on any host that rotates between several accounts.

Both detectors now consult a single canonical identity-store-membership predicate, so on a fully-migrated host `csq doctor` reports a clean bill (`Terminals: ✓`, `Legacy compat: ✓ none`).

### Fixed

#### `csq doctor` decimal_marker + legacy-terminal detectors are identity-store-aware (PR #580, closes #578)

Root cause: neither detector checked identity-store membership. A slot present in `by_slot` (OAuth UUID), `by_slot_identity` (3P API-key / Codex / Gemini recovery label), or backed by a regular-file `credentials/gemini-<N>.json` binding marker is **modern** — being idle or carrying a decimal marker does not make it legacy.

The fix extracts the three-way recovery-backed predicate that was already inlined in `audit_coexistence` into a single canonical `csq_core::accounts::profiles::is_slot_recovery_backed(base, pf, n)`, and routes **all three** consumers — the `audit_coexistence` orphan check, `detect_decimal_marker`, and the `legacy_count` terminal heuristic — through it. The three keep-sets can no longer drift apart (per `reconciler-cleanup-parity.md` Rule 4). Both detectors now fire only for genuine pre-identity-store ("pure-legacy") footprints, which aligns `decimal_marker` with its documented retirement condition.

**Trade-off:** the legacy-terminal count no longer detects a direct CC session run against a _migrated_ `config-N` (`CLAUDE_CONFIG_DIR=config-N`, bypassing `csq run`) — that case is unobservable without per-process environment inspection (SIP-blocked on macOS). The constant idle-account false-positive outweighed the rare missed case.

This is read-only diagnostic logic — no credential writes, no on-disk marker migration.
