# csq v2.8.0

**Release date:** 2026-05-17
**Prior release:** v2.7.8 (2026-05-16)
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

---

## What's new

v2.8.0 makes the **capability layer engage automatically** when a project opts in. Previously, csq's COC-aware capability layer (the institutional-knowledge surface it adds on top of `cc` / `codex` / `gemini`) required an explicit opt-in every session. As of v2.8.0 the layer auto-engages whenever the project directory contains a `.coc/` marker — and stays fully off when it doesn't. No flag to remember, no behavior change for projects that never adopted COC.

Bundled with the feature: the macOS auto-updater pipeline is hardened against the three signing-path defects that surfaced during the v2.7.8 line, so the v2.7.x → v2.8.0 in-place upgrade is clean for every platform.

If you run csq across a mix of COC and non-COC projects, this is the release where the right behavior just happens per-project without per-session setup.

### What landed

#### Capability layer: `.coc/`-gated auto-engage (an internal ticket)

The capability layer's default flips from "off unless explicitly engaged" to "auto-engage iff the working directory has a `.coc/` directory." A new `LayerIntent` enum models the three states explicitly (`AutoEngaged`, `ExplicitlyOff`, `Unavailable`) instead of the prior boolean, so the daemon and CLI agree on _why_ the layer is or isn't active. Spec 10 §10.2.2 is rewritten to make `.coc/` presence the single source of truth.

- Projects **with** `.coc/`: the layer engages automatically — same behavior you previously got by opting in every session.
- Projects **without** `.coc/`: the layer stays off. Zero overhead, no behavior change.
- The gate is per-invocation and reads the actual project directory, so switching between projects in different terminals does the right thing independently.

#### macOS auto-updater pipeline hardening (PRs #471, #474, #477)

The v2.7.8 line surfaced three independent release-pipeline defects; all are closed in v2.8.0's pipeline:

- **AppleDouble unpack failure (an internal ticket):** the macOS updater tarball is now built with `COPYFILE_DISABLE=1` and a CI gate counts AppleDouble (`._*`) entries and fails closed at non-zero. Prevents the "failed to unpack `._Code Squad Q.app`" class that broke auto-update for macOS users on the v2.7.8 cut.
- **Ungated manifest upsert (an internal ticket):** the `updater-manifest` `latest.json` upsert is gated to stable tags only. Prereleases (`-rc.N`, `-alpha`, `-beta`) no longer move the stable auto-update pointer — validated by the v2.8.0-rc.1 cut, which correctly left `latest.json` at `2.7.8`.
- **Double-base64 signature (an internal ticket):** the v2.7.8 retro-fix stopgap script double-base64-encoded the manifest's macOS signature, causing "Invalid encoding in minisign data" on the auto-updater. Root-caused and fixed; the authoritative CI path (`release.yml read_sig()`) and runbook (§7b) were already correct and are now pinned by an invariant comment so the stopgap cannot diverge again.

#### Test-infrastructure fix (an internal ticket)

A cross-module environment-variable race between the statusline and swap tests is fixed at root cause — the statusline env tests now acquire the workspace-wide test mutex (`csq-core/src/platform/test_env.rs`), eliminating a macOS-CI flake.

### Migration notes

- **No manual migration required.** Upgrading from any v2.7.x release to v2.8.0 is in-place.
- **Capability layer:** if you previously opted the layer in per session, projects that already have a `.coc/` directory now engage automatically — no action needed. If you have COC projects _without_ a `.coc/` directory and want the layer, add the `.coc/` marker.
- **macOS auto-updater:** the v2.7.x → v2.8.0 transition is handled automatically. The build is Developer ID signed + notarized + stapled; the Tauri updater verifies the minisign signature against the same baked-in pubkey (`F1C2F7FD79F952DD`) the v2.7.x line has used since v2.7.0 — the trust chain is unchanged. This release moves the auto-update pointer to `2.8.0` for all ≤2.7.x users; the v2.7.8 stopgap is retired.

### What's not yet in v2.8.0

- **CI-integrated macOS signing** (`docs/release-signing.md` § Future Work) — signing still runs on the maintainer's box; moving it into GitHub Actions requires amending `rules/ci-real-oauth-prohibition.md` plus a self-hosted macOS runner. Tracked; not blocking v2.8.0.
- **Intel Mac auto-update** — `latest.json::platforms` still only contains `darwin-aarch64`. Intel Mac users must download `csq-desktop-macos.dmg` directly. Pre-existing gap, not regressed.
- **Windows EV cert** — Windows installers ship unsigned; SmartScreen continues to show the unrecognized-publisher prompt. Foundation does not currently hold an EV cert.
