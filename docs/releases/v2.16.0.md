# csq v2.16.0

**Release date:** 2026-06-12
**Prior release:** v2.15.0 (2026-06-11)
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

---

## What's new

v2.16.0 hardens the **audit trail's trust anchors**. Three protections shipped together (issue #694):

### Roster install can no longer race the audit chain (PR #701)

`csq audit roster-install` now holds the chain-wide `.chain-lock` across its entire read-modify-write — loading `chain.json`, computing the activation sequence, writing the roster, and saving `chain.json`. Before this release, a concurrent audit write landing mid-install could produce a record that permanently fails chain verification. The install now either completes atomically or aborts cleanly with nothing written.

### Rollback tampering on the roster floor is now detectable (PR #702)

The roster version floor (the guard that stops an attacker re-installing an older, weaker roster) previously lived only in `chain.json`, where same-user file writes could silently lower it. The floor is now also anchored in the active signing-key payload in **both** key stores (file + keychain), survives key rotation, and `csq doctor` reports a new `audit_roster_floor_anchor` verdict — `confirmed`, `unconfirmed`, or `mismatch` (a mismatch means possible rollback tampering). The doctor JSON `schema_version` bumps 15 → 16.

### Non-Rust tooling can now sign rosters (PR #703)

Rosters can now ship in a **detached-signature** form: the signer signs the roster file exactly as stored on disk (sidecar `.sig` file), instead of having to byte-reproduce Rust's canonical JSON serialization. The embedded form remains the primary path and always wins when both are present. The detached path enforces the same org-root key binding, format-version gate, and rollback floor as the embedded path.

## Also in this release

- **SSH-shaped exfiltration canary** in the coc-eval harness (PR #698): a decoy SSH private key is planted in the harness's staged home; any model output echoing it fails the run with an explicit exfiltration verdict.
- **Test isolation hardening** (PRs #699, #700): the test suite can no longer touch the operator's real macOS keychain — all keyring access flows through a self-arming mock chokepoint pinned by a source-scan test. This ends the "keychain cannot be found to store 'unknown'" prompt spam that unsigned test binaries could trigger on developer machines.
- **Spec accuracy**: the `/redteam` split-state tripwire was extended and 16 stale "until X lands"-style spec framings were purged to present-state language (PRs #696, #697); specs now describe only what ships.
- One user-visible string fix: the capability layer's post-validation failure message no longer claims a corrective re-prompt happened (no such path exists; it fails closed on first attempt).

## Compatibility notes

- `csq doctor --json` consumers: `schema_version` is now **16**; the new `audit_roster_floor_anchor` field is omitted entirely on installations that have never installed a roster.
- **Downgrade caveat**: after a roster install writes the floor anchor, pre-2.16.0 binaries cannot parse the extended signing-key payload and will fail closed on key load. Recovery is upgrading back (or re-running `csq audit init` on the older version).
- No on-disk layout, CLI flag, or IPC changes otherwise; upgrade is drop-in.
