# csq v2.12.0

**Release date:** 2026-05-26
**Prior release:** v2.11.0 (2026-05-25)
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

---

## What's new

v2.12.0 closes a launch-blocker on post-A++ Codex slots, eliminates a class of false `csq doctor` `INCONSISTENT` verdicts, and ships a settings-popover refactor of the desktop dashboard header that decouples `Hide Dock icon` from `Open dashboard at launch` — two semantically distinct behaviors that were conflated in the v2.11.0 dock-hide feature.

Auto-update propagates everything; on first launch with v2.12.0 a one-time `desktop-prefs.json` migration preserves the observed pre-refactor behavior for users who had set `Hide Dock icon` on.

### Fixed

#### Identity-store-aware codex-only slot detection (an internal ticket)

Four desktop / daemon / CLI surfaces detected "codex-only slots" _solely_ by the legacy `credentials/codex-<N>.json` mirror file. v2.11.0's legacy-mirror cleanup retired that mirror on upgrade — which left any post-A++ Codex slot (identity recorded as `identities/<UUID>/identity.json` provider=codex + `credentials-codex.json`) misclassified as a broken Anthropic account. The user-visible symptoms were:

- The daemon emitted a spurious `"phase4_gate should have caught this"` WARN every 5-min poll.
- `csq doctor` reported `Identity store: ⚠ INCONSISTENT: MissingCredentialsAtUuidPath(<UUID>)` (and the sibling `MissingSettingsAtUuidPath` for the same slots that were missing `settings.json`).
- The desktop dashboard rendered the slot dimmed (opacity 0.5) as "broken Anthropic"; `discover_all`'s Anthropic-first dedup suppressed the healthy Codex entry.
- The slot's token badge showed "No token".

v2.12.0 ships `csq_core::accounts::identity_store::is_codex_only_slot` as the canonical predicate (codex-bound via `identity.json` provider OR `credentials-codex.json` present OR legacy marker; AND not anthropic-bound). All four surfaces (`discover_anthropic`, `audit_coexistence` MissingCredentials + MissingSettings, desktop `get_accounts` token-badge) now route through it. The desktop badge derives Codex token status from the JWT `exp` claim via `http::codex::jwt_exp_secs`.

#### `csq run` launch-blocker for post-A++ Codex slots (an internal ticket)

A direct sibling of an internal ticket: `csq run <N>` for a post-A++ Codex slot **hard-failed** with `Error: failed to load canonical credentials for account <N> / credential file not found: identities/<UUID>/credentials.json`. The `surface_cli_for_slot` dispatch helper keyed on the retired legacy mirror only and so routed the slot to the Anthropic launch path. v2.12.0 adds the identity-keyed branch mirroring the UUID-first resolution already in `verify_codex_canonical_is_regular_file`.

#### Gemini token badge no longer shows "No token" (an internal ticket)

Same bug class as the codex desktop badge, one surface over: Gemini slots fell through to the Anthropic else-branch of the badge builder, which loads `credentials.json` at the slot's UUID — a file Gemini never writes. v2.12.0 adds a Gemini-specific branch treating the badge like a third-party slot (binary `healthy` if `has_credentials`, `missing` otherwise, no countdown) — Gemini auth modes (API key / Service Account / OAuth) don't map to a single JWT exp.

#### Desktop renumber picker offers slots beyond 1-9 (an internal ticket)

The desktop dashboard's slot-renumber dropdown was hardcoded to offer free slots in `1..=9`. Users running slots 10+ saw `No free slots in 1-9. Use CLI csq move <N> for higher.` and had no GUI path to renumber into a higher slot. v2.12.0 scales the upper bound to `max(9, highest_occupied + 1)` — gaps and the next slot above the working set are now pickable from the dropdown. Arbitrary far jumps still go through `csq move N M`.

### Added

#### Settings popover + decoupled `Hide Dock icon` from window visibility (an internal ticket)

The v2.11.0 dock-icon-hide feature applied the macOS Accessory activation policy **and** hid the main window at launch — two behaviors implemented as a single toggle. Users who enabled "Hide Dock icon" found that the dashboard window also stopped appearing on every relaunch.

v2.12.0 separates these into two preferences:

- **`Hide Dock icon`** — controls only the NSApp activation policy (Accessory ↔ Regular).
- **`Open dashboard at launch`** _(new, default on)_ — controls whether the main window auto-shows at startup. When off, csq launches into the menu bar / tray only; click the tray icon to reveal the dashboard.

Any combination of the two is valid.

Bundled with the pref split is a refactor of the dashboard header itself: the inline `Launch on login` and `Hide Dock icon` checkboxes (which packed the title bar tight enough to wrap "Code Squad Q" on narrow widths) moved into a new **gear-button settings popover** anchored to the top right of the header. The popover has three sections — Startup (Launch on login + Open dashboard at launch), Appearance (Hide Dock icon, macOS-gated), About (version + daemon status) — with focus-managed `role="dialog"` semantics, click-outside + ESC close, and `aria-describedby` hints. The header itself is now a single non-wrapping row with the daemon status indicator + gear icon on the right.

### Migration notes

#### `desktop-prefs.json` auto-migration

If you set `Hide Dock icon` on a prior csq version, the v2.11.0 build also hid the dashboard window at launch — a side effect of the conflated dock-hide implementation. v2.12.0 reads your existing `desktop-prefs.json`; if it has `hide_dock_icon: true` and no `dashboard_at_launch` field, it materializes `dashboard_at_launch: false` on first read to preserve the observed pre-refactor behavior. **You will not see a sudden dashboard pop-up on v2.12.0 first launch.** If you want the dashboard back at startup, open the gear menu → Startup → check **Open dashboard at launch**.

The migration is null-aware: an explicit JSON `null` for `dashboard_at_launch` is treated as field-missing (preserving `hide_dock_icon` across the migration); without this carve-out a `null` would have silently failed the whole-struct deserialize and reverted `hide_dock_icon` to false. (R1 redteam finding; pinned with a regression test.)

#### CLI binary refresh

Users running the CLI directly (`~/.local/bin/csq`) should rebuild after auto-update propagates the new daemon. The version-skew guard at `csq daemon status` warns if the CLI lags the running daemon.
