# csq v2.10.0

**Release date:** 2026-05-20
**Prior release:** v2.9.0 (2026-05-19)
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

---

## What's new

v2.10.0 makes **`csq probe` trustworthy on corrupt-but-bound slots**. Before this release, a slot whose per-surface binding file existed but failed to parse fell into one of two silent failure modes the operator could not see from the probe report:

- **Corrupt Gemini binding** — `csq probe --all` reported `cell="unknown"` with a misleading `NoCredentials` diagnostic, or dropped the slot entirely. The daemon, meanwhile, would still attempt a Gemini spawn for the same slot and fail.
- **Corrupt Codex credential** — strictly worse: the dispatcher routed the corrupt slot to `codex_oauth::probe`, which reads the SHARED `~/.codex/auth.json` (codex-cli's current user) and emitted a green Cell 03 record reflecting the **wrong account's** quota. The operator saw valid-looking data attributed to the wrong slot and stopped investigating.

v2.10.0 closes both classes structurally. Corrupt-but-bound bindings are now explicitly classified as `Skipped` with `cell="{gemini,codex}-corrupt-binding"` and `exit 64` (misconfiguration). Each class carries a path-free fixed-vocabulary diagnostic that names the surface and the operator remediation (`csq logout <N>` then `csq login <N> --provider {gemini,codex}`).

Bundled with these classifications: the C2 ambiguous-binding presence-gate is extended to **presence-presence** across Gemini AND Codex — see "Migration notes" for the behaviour change this introduces.

If you operate slots with `credentials/gemini-<N>.json` or `credentials/codex-<N>.json` and `csq probe --all` has ever felt evasive about them, this is the release that makes the probe honest.

### What landed

#### `gemini-corrupt-binding` classification (an internal ticket / an internal ticket)

A new `cell="gemini-corrupt-binding"` `Skipped` outcome fires when a Gemini binding marker exists but `read_binding` returns `Err` (corrupt JSON, IO error, or a schema newer than this binary). `csq probe --all` now includes the slot in its output (recovered via a direct `is_gemini_corrupt_bound` scan that complements `discover_gemini`'s strict-parse drop), and the diagnostic surfaces the path-free error-kind tag with a concrete remediation hint.

The fix also closed a latent C2 hint-path leak (`ambiguous_binding` previously interpolated the absolute identities-store path into its `observed_shape` — now path-free fixed-vocabulary).

#### `codex-corrupt-binding` classification + C2 presence-presence widening (an internal ticket / an internal ticket)

The Codex analogue. A new `cell="codex-corrupt-binding"` `Skipped` outcome fires when `credentials/codex-<N>.json` is present but `credentials::file::load` fails. The dispatcher's new Step 3.5 short-circuits before the Anthropic-cred-None → `codex_slot_present && discovery_codex_match → codex_oauth::probe` fall-through, closing the silent mis-attribution path.

Three structural changes ride alongside:

- **`SkipReason::CorruptBinding` promoted to a struct variant `{ surface: Surface, kind: &'static str }`** — single path-free audit surface for both Gemini and Codex. The `as_diagnostic` arm now branches on `surface` to pick the per-surface literal prose, with `Surface::ClaudeCode` deliberately `unreachable!` (corrupt-binding is conceptually a marker-or-credential file, not an Anthropic identity).
- **`CredentialError::error_kind_tag(&self) -> &'static str`** — five fixed-vocabulary path-free tags (`credentials_not_found`, `credentials_malformed`, `credentials_io`, `credentials_invalid_account`, `credentials_none`). Adopted at four `discovery.rs` warn! sites that previously interpolated `error = %e` (which echoes the absolute path via `Display`). The in-scope sweep (per zero-tolerance discipline) fixed three sibling sites alongside the originating `discover_codex` site that the issue named.
- **`is_codex_bound_slot` lifted from `setkey.rs` into `csq-core/src/providers/codex/provisioning.rs`** alongside a new sibling `is_codex_corrupt_bound`. Single source of truth, no re-export drift, matches the Gemini analogue.

#### Host-isolation Gemini gate fix (an internal ticket)

A spec-08 MED-03 issue: `csq doctor`'s host-iso Gemini gate keyed off a dead path, silently suppressing the gate. Fixed at root; the doctor's host-iso check now fires for canonical Gemini slots without providers-path artifacts.

#### Spec 11 → rev `1.0.3`

`specs/11-probe-driven-verification.md` documents the two new cross-cell skip classes (`gemini-corrupt-binding` at §11.2 rev `1.0.2`; `codex-corrupt-binding` + C2 presence-presence extension at §11.2 rev `1.0.3`). `SCHEMA_VERSION` unchanged at `"1.0.0"` — the new cell names + `SkipReason` shape are data within the existing JSON shape.

### Migration notes

- **No manual migration required for the corrupt-binding classifications.** Upgrading from v2.9.0 is in-place. The new classifications fire only on the next `csq probe` against slots whose bindings happen to be corrupt — for healthy slots, behaviour is unchanged.

- **Behaviour change — C2 ambiguous-binding now presence-presence across surfaces.** The C2 guard at `probe_slot` Step 2 was extended from:

  ```
  is_gemini_bound_slot(base, slot) && anthropic_present
  ```

  to:

  ```
  (is_gemini_bound_slot(base, slot) || is_codex_bound_slot(base, slot)) && anthropic_present
  ```

  **A slot with valid Codex credentials AND valid Anthropic identity-store credentials** — previously a silent green Codex probe — now **FAILs `ambiguous-binding`** (exit 1). Operators with such side-by-side configurations must `csq logout <N>` and re-bind to a single surface. This is the symmetric application of an internal ticket's load-bearing C2 insight ("a slot carrying artifacts for two surfaces is ambiguous regardless of parse status") to the Codex side. Documented in spec 11 §11.2 rev `1.0.3`.

- **`csq probe --all` output**: corrupt-but-bound slots that were previously silently dropped (Gemini) or silently mis-attributed (Codex) now appear in the report as explicit `Skipped` rows. Scripts parsing `csq probe --all --json` should expect new `cell` string values: `"gemini-corrupt-binding"` and `"codex-corrupt-binding"`. The `failed_assertion` field on these records starts with `"prerequisite:"` (routed to exit code 64 by the existing `exit_code_for` classifier).

- **macOS auto-updater:** the v2.9.0 → v2.10.0 transition is automatic. Developer ID signed + notarized + stapled; minisign signature verifies against the same baked-in pubkey (`F1C2F7FD79F952DD`) used since v2.7.0 — trust chain unchanged. This release moves the auto-update pointer to `2.10.0`.

### What's not yet in v2.10.0

- **an internal ticket — `SkipReason::NoCredentials` path leak.** A separate sibling fix in the same class as an internal ticket's `ambiguous_binding` and an internal ticket's `discover_codex` warn! leak fixes. Tracked; lands in a follow-up cycle.
- **an internal ticket — FM-5 wrong-variant Codex payload silently dropped.** A Codex-prefixed credential file whose payload parses as Anthropic shape (the `cf.codex().is_none()` arm at `discover_codex:523-530`) is `continue`d without emission. Distinct fix shape from an internal ticket's corrupt-JSON case; filed during the an internal ticket analyze cycle.
- **RN1-F (terminal `accounts`-field deletion)** — still soak-gated by design (WINDOW-CLOSE N=2). v2.10.0 advances an internal ticket's soak gate by one release.
- **CI-integrated macOS signing**, **Intel Mac auto-update**, **Windows EV cert** — unchanged from v2.9.0 status.
