# csq v2.20.0

First release since v2.19.0 (2026-09-07) — **842 non-merge commits**
(`git rev-list --no-merges v2.19.0..origin/main` at c8291aaa), 394 `fix` and 70 `feat`.
No breaking changes; minor per semver.

## Highlights

### Third-party slots: the context window is now the model's real one

Auto-compaction had never fired on a third-party slot. csq points the CLI at a
provider's endpoint, and the CLI only knows a context window for models it
recognises — so on a slot behind that redirect it had no window to compare token
usage against, and the trigger that would have compacted the conversation never
ran. The window variable had been set for one provider only; zai, DeepSeek and
MiniMax were silent.

Setting it turned out to have a subtlety worth stating, because three releases'
worth of values chased it:

- The window is **not a tuning knob**. It is the model's own context window, and
  the CLI applies its **own** safety margin as a fraction of whatever you declare.
  Declaring less than the real window compacts early; declaring more risks a
  context-limit error at the boundary. The value was first set to a flat 90%, then
  960k, then corrected to the model's own published figure.
- Kimi's guide mandating `1_048_576` is not house style — `kimi-k3`'s real window
  **is** `1_048_576`. It is the model's context verbatim, which is the principle.
- The window variable alone can be inert. The CLI is reported to cap unrecognised
  model ids at 200k and take the smaller of the two, which clamps a window-only
  setting straight back down — the exact symptom being fixed. `csq` now pins the
  companion maximum-context variable to the same value.

All four third-party providers (Kimi, Z.ai, DeepSeek, MiniMax) now declare
`1_048_576` uniformly, and each provider block records the trade in place.

**DeepSeek's default model changed to `deepseek-flash[1m]`.** It previously
defaulted to `deepseek-v4-pro` and overrode to the flash variant only at the
cheapest tier — so within one provider, one tier was sized from the model's real
window and the others from the CLI's own assumption. Kimi and Z.ai had already
defaulted to their 1M variant; DeepSeek was the outlier.

### Model and pricing data is now versioned and inspectable

Model metadata and historical pricing moved out of compiled-in code into a
versioned manifest that ships with the binary and can be replaced at runtime.
`csq models` gained local maintenance — list, show, validate, install, reset —
plus runtime switching, so a model added or repriced between releases no longer
waits for the next build. An invalid manifest fails loudly rather than being
partially applied, and a manifest-shaped gap is reported as a manifest problem
rather than being guessed at.

Bundled with it: DeepSeek V4.1 Flash is priced correctly across its historical
cutover, so usage recorded before the change is re-priced rather than left at the
numerator.

**Claude Opus 5.5** is in the catalog (1M context, 128K output, $4 / $20 per
million input / output tokens). Several Claude prices were wrong and are
corrected against Anthropic's published price list: Opus 4.5, 4.6, 4.7, 4.8 and
Opus 5 were estimated at $15 / $75 and are $5 / $25; Sonnet 5 was $3 / $15 and is
$2 / $10. Cost estimates for those models were three times too high (Sonnet 5:
1.5 times). On Google Cloud and Amazon Bedrock the provider bills you; regional
endpoints there cost about 10% more than these list prices.

`csq models switch claude '<model>[1m]'` now keeps the `[1m]` suffix. It used to
drop it, and Claude Code sizes the context window from that suffix — so a slot
switched to a 1M-context model quietly ran with 200K.

### Session history now follows the account, not the slot

Switching accounts used to strand your conversation history behind the slot it
happened to be recorded on. csq redirects a slot's home directory to isolate the
account's identity — and conversation state lived in that same directory, so it
was isolated along with it. Swap to another account and your Codex or Kimi
history was still sitting under the previous slot.

`csq sessions share` fixes that, for the surfaces where it applies:

```
csq sessions share --surface codex            # migrate this surface's history
csq sessions share --surface codex --dry-run  # show what would move, change nothing
```

Migration merges rather than clobbers. Byte-identical files are deduplicated;
files that differ keep **both**, the displaced one under a suffixed name; and
JSONL indexes deduplicate on their own record identity rather than on position.

A real (non-dry-run) migration refuses to touch a surface while a vendor process
is live, checking two independent signals — a process-name scan and csq's own
per-slot bookkeeping. Either signal alone is enough to refuse, and an unreadable
process list is treated as "cannot determine", which also refuses. `--force`
overrides, prints exactly which process it is overriding, and requires the
surface to be named explicitly so a bulk override of everything at once is not
available. Dry runs are never gated, because a dry run changes nothing.

For Codex, the command also merges each slot's **conversation index** (the thread
list and the names you gave threads, which `resume` reads) into one shared index,
keeping every slot's rows and a backup of each original. It also repairs index
entries that still point at a closed terminal's temporary folder, so they point at
the same transcript in the shared store. Run it once with no Codex session open;
after that every account reads the same index and `resume` works across swaps.

Newly authenticated Codex, Kimi and Grok slots now join the shared store at login
instead of quietly keeping private history. That step is **advisory**: if the
migration cannot proceed the login still succeeds and the skip is printed, because
reporting a refusal as success is worse than the refusal.

### The daemon can hold a secondary role on a second machine

If you run csq on more than one computer, both daemons were refreshing the same
accounts — and each refresh returns a **new** refresh token, invalidating the
other machine's stored copy. The result was a slow, spreading authentication
failure: a handful of slots at a time, alternating unpredictably between hosts.

The second machine's daemon can now be a **follower**: it polls usage, answers
the local command socket, sweeps terminal directories and syncs credentials
exactly as before, and performs no token refresh at all. One machine stays the
leader. The setting persists across app launches rather than being a one-shot
flag, and a follower whose tokens go stale says so in `csq doctor` instead of
failing mysteriously.

### Switching accounts now tells the truth

**You can now switch a running Codex session to another account without leaving
it** (macOS and Linux). Run `!csq swap N` inside Codex: csq launches Codex under a
small supervisor, which checks the target account, restarts Codex on it and
resumes your most recent conversation (`codex resume --last`). The swap command
waits for the supervisor's answer and reports exactly what happened — accepted or
refused, with the reason — and the supervisor, not the command that asked, records
the outcome in the audit trail. Codex conversation history is shared across
accounts (`csq sessions share --surface codex`, above), so the resumed
conversation is the one you were in.

`csq swap N` between two Codex accounts used to repoint the terminal and report
success while the **old** account stayed live — the vendor's own auth-reload
guard silently ignores a credential change belonging to a different account. The
deciding logic was implicit, encoded cell-by-cell across surface pairs with a
catch-all, and Codex fell through it. It is now an explicit, exhaustive
per-surface capability with no catch-all arm, so a new surface fails to compile
until its behaviour is named rather than inheriting the wrong default silently.

Also on the swap path:

- A Codex slot provisioned on a current build is accepted when its credential
  lives in the identity store with no legacy mirror — the check demanded a file
  that had been retired, so a fully working slot was refused.
- A Kimi or Grok session is now told the **real** reason it cannot swap in place,
  instead of being told it is not inside a csq-managed session (it was) and handed
  three environment variables that had nothing to do with it.
- The source path is validated for containment before any side effect, and the
  check requires a strict descendant rather than accepting the base itself.

### Billing numbers that match what you actually used

The desktop billing card showed new input plus replies only. Every token the
provider served **from cache** was missing from the figure — on the maintainer's
own slot, roughly 857 million omitted against ~10.5 million displayed, close to
two orders of magnitude of understatement. Each window total is now the sum of
four disjoint dimensions (new input, replies, cache written, cache reused), added
exactly once.

The card also stopped implying the number is a bill. It now says plainly that the
figure is estimated **on this computer** from session records over a rolling
window, and a details panel exposes the estimate's boundary: the per-dimension
breakdown, how many requests were counted, how many came from helper sessions,
how many repeated readings were merged, how many requests ended on disagreeing
readings, and how many records carried no request id.

Underneath, accounting moved from per-transcript-record to **per request**. The
CLI appends a usage snapshot on every streaming update, so a single API call left
several usage-bearing records and the scanner had been summing them all —
counting each request's tokens once per snapshot. Requests are now identified and
finalized to their last snapshot, and the cases where that disagrees with a
per-field maximum are **counted** rather than resolved silently. The scan also
descends one level into helper-session transcripts, which it never read before.

### Robustness and platform fixes

- **The community edition now builds with the dependency versions the enterprise
  edition tests.** Its lockfile used to be regenerated at extraction, which pulled
  the newest compatible release of every dependency — 260 differed at this
  release. One of them switched the Windows C runtime to static linking and broke
  the Windows test build. Tests also run as separate library, integration and
  documentation passes, as in the enterprise CI.
- **Self-update on Windows was broken.** The signature URL was built from the
  bare platform name while the binary URL correctly appended `.exe`, so the
  updater asked for an asset that has never existed. It failed closed — refusing
  rather than accepting an unverified download — which is why it presented as
  "update does not work" rather than as anything alarming.
- **Atomic file replacement now handles a cross-filesystem move.** Renaming
  between two volumes fails with `EXDEV`, and that became reachable once csq
  started placing identity and shared session state in directories an operator may
  put on another disk. On that error only, the write falls back to copy, flush and
  rename **within** the target directory, preserving atomicity at the target.
  Every other error still propagates loudly.
- **`csq run` no longer launches a command-line tool that csq is concurrently
  replacing.** Observed live: an upgrade completed between the version check and
  the launch, leaving a session pinned to the old package and stuck indefinitely.
  csq now sequences the two rather than handing you a session running against a
  binary it is swapping out from under it.
- **Credential reads are bounded by a timeout**, and the read boundary
  distinguishes "absent" from "could not read" rather than treating both as
  missing. A locked or slow credential store no longer hangs a command.
- **One rule now decides every write to Claude Code's keychain entry, and it never
  destroys a sign-in it cannot account for.** csq copies each terminal's sign-in
  into the keychain entry Claude Code reads. Before this release several csq paths
  wrote that entry independently, and one treated "the keychain could not be
  asked" the same as "there is nothing there", which could overwrite a token Claude
  Code had just refreshed for itself. Every path now goes through a single
  decision: csq writes only when the entry is empty or holds a sign-in it
  recognises; if the entry holds a valid sign-in csq has never seen (for example a
  `/login` you did inside Claude Code), csq first adopts it as an account and only
  then proceeds; if the entry cannot be read or understood, csq changes nothing.
  Other data Claude Code keeps in that entry (such as MCP server sign-ins) is
  preserved rather than replaced.
- **Switching accounts is all-or-nothing, and cannot quietly bring an old sign-in
  back.** A switch either repoints the terminal and its keychain entry together or
  rolls back. csq now remembers a short history of each account's past tokens — as
  one-way fingerprints, never the tokens themselves — so it can tell "this is an
  older token of a known account" from "this is someone else's sign-in", and a
  clean-up that could not finish earlier is completed later only if the keychain
  still provably holds the old account. A terminal no longer inherits the previous
  account's plan tier, and your own plan tier is kept across token refreshes
  (losing it made Claude Code fall back to a smaller model).
- **Keychain access is serialised and time-limited.** Every csq path that writes
  the keychain holds a per-terminal lock and every keychain call has a time limit,
  so two csq processes cannot overwrite each other's update and a locked or
  unresponsive keychain delays a launch rather than hanging it. A refusal from the
  keychain is no longer reported as "no such item".
- **The daemon's token refresher contains a crash and handles Codex rate limits
  separately.** A crash during one refresh cycle is caught, logged with tokens
  redacted, and followed by the usual keychain re-sync; the next cycle runs
  normally. A Codex rate-limit response now pauses only Codex refreshes for that
  cycle.
- **Every keychain call is genuinely time-bounded, including Codex's.** Two
  keychain reads on the Codex path had no timeout at all, and the shared timeout
  could be outlived by a helper process holding the output open. A slow or stuck
  keychain now cannot hang a command.
- **`csq doctor` on Windows no longer reports a broken outbox as healthy.**
  Windows reports "a folder in this path is actually a file" with the same error
  as "this path does not exist", so a broken path read as an empty, healthy
  outbox. It is now reported as the problem it is. Found the first time the
  Windows test suite ran against this release.
- **A stale provider binding is cleared even where the system credential service
  is unavailable.** On a Linux host with no system secret service, the cleanup
  step was unreachable for every authentication mode, so a successful login could
  leave a slot bound to two providers at once. The cleanup now consults the
  records that actually carry the mode, and where it genuinely cannot proceed it
  refuses loudly and names the slot rather than proceeding on a guess.
- **A newly created Codex database is written outside the terminal handle
  directory**, so a cold slot no longer depends on cleanup that a normal exit can
  bypass. `csq login --provider codex` also no longer opens a browser when it is
  not running interactively — previously a scripted or automated login printed a
  prompt nobody could answer **and** hijacked the frontmost browser window.
- **The desktop app no longer downgrades the command-line tool.** On a Finder
  launch the app seeds its own search path with the package-manager location ahead
  of the canonical one, so its keep-in-step step refreshed the package-manager
  copy and let the binary your shell actually runs drift behind — the app was
  causing the version-skew warning it exists to prevent. The canonical location now
  wins.

- **Your sign-in token no longer appears in the process list when csq writes
  the keychain.** csq used to pass the whole sign-in record to macOS's
  `security` tool on its command line, where any other program on the machine
  could read it with `ps` for the moment the write took. It now sends it over
  the tool's input instead. One exception, described under Known limitations:
  very large records still use the old method.
- **Files holding secrets are private from the moment they are created.**
  About 30 places that write sign-in tokens, API keys, account emails or
  signing keys used to create the file readable by other users and lock it
  down a moment later; they now create it private (owner-only) in one step and
  refuse to follow a planted symlink. Four of those files were never locked
  down at all and stayed readable by other users; they are fixed too.

### Release and verification integrity

Two classes of "confidently wrong" tooling failure were removed at the root.

**The release tooling trusted whatever `python3` happened to be on the path.**
Roughly a dozen release and verification paths shell out to `python3` and read its
output as their answer. Measured on this host, that resolved to a 54-byte stub that
printed a directory and exited **0 for every input** — so a build step chased a
nonexistent path, and gates that read the interpreter's output produced empty
results that rendered as verdicts. The clean gate reported the tree clean while
reading nothing.

Both obvious guards pass on that stub: `command -v` and `test -x` are both
satisfied by a file that is executable, on the path, and always exits 0. Only
**executing** a candidate and checking its **answer** tells a working interpreter
apart from one that merely accepts being called. Every release path and every
verification gate now resolves an interpreter proven that way, and — critically —
reports "cannot measure" rather than a verdict when none can be verified. The
gate self-tests were converted too: a harness vouching for a fixed gate from an
unmeasured run is the same defect one level down.

A follow-up hardened the probe itself. Its original test was `print(3+4)`, which
cannot detect an interpreter that dies inside a core system call. On this host it
accepted one that segfaulted on `os.pipe()` — so a suite reported a segmentation
fault instead of a verdict. The probe is now a single execution answering three
questions at once: does it run and print the demanded value, can it create a pipe,
and is it new enough for the syntax three of csq's scripts use.

**A trunk could be pushed to with nothing having checked it.** The `dev` branch
runs no CI by construction — every workflow triggers on `main` or on tags only —
so nothing downstream catches a bad push. csq already had both halves of a defence:
a preflight that writes a receipt keyed to the exact commit it checked, and a guard
that refuses a push no receipt vouches for. Nothing invoked either. The missing
invocation site is now a version-controlled hook that ships with the repository
instead of dying on the next clone, gated to the trunk branch, propagating all
three outcomes, and **blocking** on an unrecognised result rather than failing open.

Smaller gate corrections in the same vein: the CI lint preflight read the first
`env:` block anywhere in a job, so an unrelated step's block was merged into the
derived command — a false "cannot determine" that sends an operator to fix
something that is not broken; a gate selected its candidates from
free-form prose alone and now also reads the machine-checkable marker form, with
per-citation historical opt-out; and the documentation citation gate now covers
live docs and root entrypoints, not only a subset of the tree.

## Known limitations

- **Very large keychain sign-in records still use the old write method.**
  macOS's `security` tool cuts off input lines longer than 4 KB, so a sign-in
  record above roughly 1.9 KB (typically several MCP server sign-ins stored
  alongside it) is written the way v2.19 did, with its contents briefly
  visible to other programs on the machine, and a warning in the log. Nobody
  is worse off than on v2.19. Removing this fallback is tracked in an internal ticket.
- **MiniMax's window declaration exceeds its recorded limit.** Its model id is
  bare, so the companion maximum-context variable is **live** for it and the CLI
  will believe the declared window against a smaller real one. Adding `[1m]` to
  the id would make it behave like the other three. Called out in the provider's
  own configuration block, not left implicit.
- **Kimi sets its window with no companion variable.** The same clamping mechanism
  may make its documentation-mandated window inert. Left as an open finding for
  the maintainer to rule on; the tests deliberately do not pin it either way.
- **A local model with no measured context window gets no window variable at
  all.** Not a guess, and not an oversight — deliberately silent rather than
  confidently wrong.
- **Codex index sharing is a one-time manual step.** `csq sessions share
  --surface codex` must run once with no Codex session open, and again after
  adding a new Codex account. Doing it automatically at launch is tracked in
  an internal ticket.
- **Kimi and Grok have no process-name liveness detector**, so a real session
  migration on those two surfaces always refuses without an explicit override.
  Conservative by design rather than a regression.
- **Intel Mac auto-update** remains unavailable: the update manifest still lists
  only `darwin-aarch64`, so Intel Mac users download the `.dmg` directly.
  Pre-existing gap, not regressed.
- **Windows installers ship unsigned**; SmartScreen shows the unrecognized-
  publisher prompt.

## Upgrading

No action required. `csq` auto-updates, and the desktop app updates through its
own channel.

Things worth a look after upgrading:

1. **Third-party slots now auto-compact.** If you run a Kimi, Z.ai, DeepSeek or
   MiniMax slot, long sessions will begin compacting where they previously grew
   unchecked. That is the fix, not a regression.
2. **DeepSeek's default model changed** to `deepseek-flash[1m]`. If you pinned a
   model explicitly, your pin still wins; if you were relying on the previous
   default, re-check the selector.
3. **The default effort for Claude account slots is now `medium`** (it was
   `high`). This is csq's default only: an `effortLevel` you set in your own
   Claude Code settings, or on a specific slot, still takes precedence.
4. **If you use Codex on more than one account**, close your Codex sessions and
   run `csq sessions share --surface codex` once, so `resume` finds your
   conversations after a swap.
