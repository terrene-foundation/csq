# csq v2.19.0

First release since v2.18.0 (2026-07-17) — **1,260 commits**, 448 `fix` and 114 `feat`.
No breaking changes; minor per semver.

## Highlights

### Model catalog correctness

- **Claude Opus 4.8's context window is now 1M**, corrected from a `200_000`
  literal that had been carried forward untouched since v2.0 across the
  4.6 → 4.7 → 4.8 renames. On a 1M model the stale figure over-reported context
  use fivefold in the statusline.
- **Deployment-suffixed model ids now resolve.** `ModelCatalog::find` matched
  exactly, so a Vertex id (`claude-opus-4-8@default`) or a CC window annotation
  (`…[1m]`) missed the catalog entirely and the statusline silently fell back to
  Claude Code's own ~200k assumption. Both suffixes are now normalised for
  lookup; the stored id is never rewritten and exact matches still win.

### CI integrity

- **Runner-fleet routing.** The org pool holds two disjoint Linux fleets that
  both answer to `[self-hosted, Linux, X64]`; roughly a fifth of jobs landed on
  a fleet provisioned for none of csq's needs. That single fact produced three
  separately-filed symptoms — eval-harness "flakes", `Rust tests (enterprise)`
  failing `claude binary not found on PATH`, and an apparent loss of
  passwordless sudo. Every job is now pinned to the provisioned fleet, with
  `scripts/ci/assert-runner-prereqs.sh` asserting the capability directly so a
  mislabelled runner fails in seconds with an accurate message.
- **An always-running `CI gate`.** Path-filtered guards could not be required —
  a required check skipped by its own path filter never reports and blocks the
  PR forever. One unconditional aggregator now derives its verdict from whatever
  checks the diff actually triggered, so guards including the community
  moat-leak check finally block a merge without removing a single `paths:`
  filter.
- **Release-drift detection.** Nothing measured the gap between `main` and the
  last release tag; `version-lockstep` stayed green because the three version
  strings agreed with each other while all three were equally stale. A new gate
  measures the gap and warns before it fails.
- **Job-budget census** of per-PR runner demand against declared pool capacity.

### Determinism and hygiene

- TTL-cache tests no longer race the wall clock (three `thread::sleep` calls
  removed; the module now runs in 0.00s and asserts on the expiry predicate
  directly).
- Phase-2b binary resolution moved behind the `CliRunner` seam, so stubbed tests
  no longer require Claude Code installed on the host.
- Per-slot `ANTHROPIC_MODEL` pinning for cloud slots, which previously hung
  silently on a no-quota default.
- The desktop frontend is now enrolled for dependency updates; it had shipped
  without any update path.

### SDK

The governed authoring lifecycle (`csq.authoring_intent.v1`,
`csq.authoring_session.v1`) is advertised and executable, with session memory
and session-to-decision-procedure distillation.

## Upgrading

No action required. `csq` auto-updates; the desktop app updates via its own
channel.

Operators pinning a Claude model on a Vertex or cloud slot may want to review
the model id: a trailing `[1m]` selects the 1M-context variant where the
provider offers it.
