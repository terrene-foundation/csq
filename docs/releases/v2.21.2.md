# csq v2.21.2

**Release date:** 2026-10-25
**Prior release:** v2.21.1 (tagged 2026-10-22).
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

---

## What's changed

### Kimi slots default to K3.1 Pro

New Kimi third-party slots now default to Kimi K3.1 Pro with the 1M context window, and a
256K K3.1 Pro row is selectable beside it. Existing slots still pinned to the retired
`kimi-k3[1m]` default are migrated once, in place: key order, formatting and line endings
of the settings file are preserved, and a slot whose settings file is locked, unreadable or
not a regular file is skipped rather than half-edited. Switching a model now moves its
context-window keys and the Kimi subagent model with it. K3.1 Pro usage is shown as unrated
until the vendor's pricing is verified.

### Settings changes can no longer race each other

Every writer of a slot's settings file — `csq setkey`, `csq rmkey`, model switching, the
Kimi migration, the daemon's legacy `apiKeyHelper` cleanup and the desktop app — now takes
the same locks in the same order and reads the file without following links. When a write
cannot proceed, csq says why: another writer holds the lock, the lock is unusable, the slot
is unbound, or which stage failed. The desktop app runs these writes off its interface
thread, so the window stays responsive while they wait.

### A bad connection no longer aborts a Gemini or Claude sign-in

During a Gemini or Claude sign-in, csq listens on a local loopback address for the
browser's callback. Until now one reset, stray, slow or over-long connection to that
listener aborted the whole sign-in. Each such connection is now dropped and logged on its
own, the listener keeps waiting for the real callback, and at most 16 connections are
handled at once. A sustained flood of local connections can still crowd out the automatic
callback; when that happens, pasting the code by hand still completes the sign-in.

### Stuck or cancelled sign-ins are cleaned up on every OS

The sign-in flows for Claude, Codex and the native logins now keep custody of the login
helper process from start to finish. When a sign-in is cancelled or runs past its
deadline, the helper and every process it started are stopped and confirmed gone, the
sign-in lock is released by the thread that took it, and a half-finished login is never
published as the account's credential. This holds on macOS, Linux and Windows, so a stuck
sign-in no longer leaves a background process or a held lock behind.

### The DeepSeek key check catches a rejected key

Checking a DeepSeek API key now fails when DeepSeek rejects the request (HTTP 400). It
previously reported such a key as working.

### Windows desktop updates wait for a clean shutdown

On Windows, the desktop app now admits an installer update only after its background work
has been joined and the app has verifiably shut down, and it keeps that admission closed if
the update could not be verified. This prevents an update from replacing files the running
app still holds.

### Dependency and advisory housekeeping

Tokio is updated for its `AsyncFd` safety advisory, a yanked `spin` release is replaced,
and RUSTSEC-2026-0387 (`crypto-bigint` 0.5.5; fixed upstream in 0.7.6, but still
resolved at 0.5.5 in csq's dependency graph) carries a dated exception in the enterprise
dependency-policy gate, valid through 2026-11-04 and applied only after a fail-closed check
of the exact dependency path. Desktop interface dependencies (Tauri API and plugins, Svelte, Vite) are
bumped, and the third-party attribution bundles are regenerated for both editions.

## What's improved (developer-facing)

The release dependency-policy gate now passes the dependency tool's error output straight
through, so a refusal shows its real cause. Several shared test locks and timing-sensitive
tests were reworked to decide on observed events and enforced limits instead of host speed,
removing a set of rotating CI failures that were not product defects.

## Upgrading

No command or on-disk format changed. Kimi slots on the retired default are migrated
automatically the next time they are launched. `csq --version` reports `2.21.2`.
