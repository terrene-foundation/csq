# csq v2.21.4

**Release preparation:** 2026-10-31
**Prior release:** v2.21.3.

Both editions ship this release: `csq` (community, Apache-2.0, Terrene Foundation) and
`csq-ee` (enterprise edition, commercial licence). Items below apply to both unless a
section says otherwise.

---

## What's changed

### Run a model call against a stored API key, with a spending limit

`csq exec --pool <provider> --model <exact-model-id> --max-tokens <count>` now runs a
single OpenAI or Anthropic request using a key from the API-key pool. Each call reserves
its worst-case cost against that key's budget before it is sent, and settles the real
cost afterwards. A model with no checked price is refused instead of guessed. The command
never touches a subscription account, starts a provider CLI, or falls back to another
credential. If the key store cannot be read, the failure is named as a store outage and
is kept distinct from one unreadable key, and retries, key rotations and a corrected
system clock do not lose or double-count spending. The contract is specified in
`specs/33a-pool-execution.md`.

Every deadline and timestamp in the pool path now comes from one injected clock, so a
changed or frozen system clock cannot expire an admission early or leave a budget hold
behind.

### Retiring a finished branch now works for the shapes v2.21.3 left behind

Branch retirement used to recognise only branches named in landing trailers, so a branch
whose tip became the integration tip, or one that reached `main` through a pull-request
merge, could not be retired. Retirement now proves the work is already in the integration
branch before it changes anything: it requires the branch's own history to witness its tip,
checks that the content survived the merge, and refuses replaced or grafted history. A
forged merge cannot certify a branch.

### Stricter dependency-advisory gate for csq-ee

The enterprise advisory check now reads the advisory policy as structured data and scans
the full native-harness dependency graph, which no earlier run had covered. The
`crypto-bigint` warning can no longer be silenced by an ignore entry, each exception's
expiry date is enforced, and the shipped binary records the features it was built with.
Release builds run that check before signing, and the maintainer macOS app is checked
before it ships.

## What's improved (developer-facing)

- **Shell hooks run once per event.** The Bash and prompt hooks are folded into one Node
  process per event, with a fail-closed census of the subprocesses they may start, no
  automatic `.env` creation, and bounded post-edit work. A write watcher and a parity suite
  guard the change.
- **Sign-off and CI harness reliability.** The test watchdog reports a leader that exited
  before the process snapshot and treats a killed-but-unreaped zombie as dead. A skipped
  kill now names the process when its start time changed. Several time-sensitive login and
  pool tests no longer race a wall clock, and a fixture receipt is published atomically.
- **Build-target size guard.** When the CI cargo-target high-water guard refuses a run, it
  names the offending entries (path, type, mode, owner, reason) and no longer claims a
  complete scan when it stopped at the first offender.
- **Preflight scope errors** name the stale worktree path and the prune remedy.
- **Release and CI inputs.** The Windows Rust-input census was regenerated for the pool
  clock changes, and the maintainer-app feature check runs in its own publish step.

## Also landing in this release

These lanes are not yet in the base this preparation was cut from. They land in the same
batch, ahead of the tag:

- **Branch retirement keeps a hardened local ledger and creates no archive refs (an internal ticket).**
  Retiring a branch deletes it and records the outcome in a protected local ledger instead
  of leaving `refs/csq-archive` or `refs/archive/landed` copies behind, which had quietly
  recreated the branch store that retirement exists to remove.
- **A login no longer pauses when started in the background (an internal ticket).** A desktop or CLI
  `csq login` started from a background process group is no longer stopped by the
  terminal-output signal (SIGTTOU) before it can run, so the sign-in completes instead of
  failing at once.
- **The Svelte desktop test leg in preflight.** Sign-off now runs the desktop UI tests
  as their own isolated leg, with a fixed tool search path, a scrubbed environment and
  process cleanup, so a UI regression is caught before landing rather than in CI.
- **cx-backlog-ab fixes.** Follow-up fixes from the cx backlog batch.
- **Records.** Journal entries, session notes and the release ROADMAP row for this cut.

The final list of these lanes is fixed when they land; the release owner confirms it
against the landed commits before signing.
