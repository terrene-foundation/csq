# csq v2.21.0

**Release date:** 2026-10-06
**Prior release:** v2.20.2 (2026-10-03)
**Checksum / signature:** see artifact `SHA256SUMS` and `.sig` files on the GitHub Releases page.

## What's new

### Sessions can talk to each other: cross-CLI messaging

A Claude Code session and a Codex session running on the same machine can now
ask each other questions, answer, and coordinate while both are working. This
works in all four directions: Claude to Claude, Claude to Codex, Codex to
Claude, and Codex to Codex. csq stores and delivers the text and never runs
anything a message says; the receiving agent, and its person, decide what to do.

- **Send and answer.** `csq sessions send <pid>:<started_at>|<name> --message
  <text>` sends a message; `csq sessions inbox --messages` and `csq sessions ack-message` read
  and acknowledge them. A reply goes only back to the session that wrote the
  message.
- **Inside the agent.** Sessions started with `csq run` get a small local
  messaging server (`csq mcp-messaging`) with `list_sessions`, `send`, `reply`,
  `set_name`, inbox and acknowledge tools, so the model can message a peer
  without shelling out.
- **Messages arrive mid-task.** Claude Code surfaces a waiting message on its
  next turn and in the status line. A Codex session that is sitting idle is
  woken when a message is sent to it.
- **Name your sessions.** `csq sessions name <name>` gives the current session a
  name; `csq sessions list` shows each session's name, repo and branch, and
  `send` accepts a name instead of a pid. Two sessions with the same name are
  refused rather than guessed between.
- **Safe by construction.** The sender is always proven from the calling
  process, never typed in. Only live sessions started by csq on this machine can
  send or be reached. Text from a peer is always presented to the model as
  untrusted input. There is no network route and no daemon involvement.
- **Off switch.** `CSQ_MESSAGING=off` registers nothing for that session.

Specification: spec 32 (`32-cross-cli-messaging.md` and
`32a-cross-cli-messaging-surfaces-delivery.md`).

### Directives to running sessions

`csq sessions list` now reports every live session as a stable, machine-readable
list, and a directive can be delivered to a session and acknowledged by it. A
status-line notice shows when one is waiting (spec 31).

## What's faster and more accurate

- **`csq sessions list` on macOS is about 1 second instead of several
  minutes** on a busy machine. Session lookup now reads each process directly
  and says plainly what it could not see, instead of silently listing nothing.
- **Desktop usage screens use less CPU and memory.** The parsed usage history is
  cached per account and refreshed only when a file changes.
- **Cost in the status line for non-Anthropic providers** is priced from the
  provider's own model rates, adds up sub-agent work, and shows `$?` when a
  model has no known price rather than a wrong number.

## What's fixed

- **A login stuck as "unharvested" no longer blocks `csq swap`.** When a session
  held an older login of the same account, csq refused to swap and the terminal
  stayed stuck. csq now recognises an older login that belongs to the same
  account, and the warning names the session that holds it.
- **Session lookup refuses to guess.** Lookups that cannot prove which process is
  which (a reused process id, an unreadable process table, a restricted Linux
  `/proc`) report "undetermined" instead of picking one.

## After upgrading

- Start sessions with `csq run` (or `csq <N>`) to get messaging; a bare
  `claude` or `codex` started outside csq cannot send or receive.

## Compatibility notes

- New wire types `csq.message_receipt.v1` and `csq.message_inbox.v1`; the
  `csq.sessions.v1` listing gains optional fields (`label`, `label_source`,
  `repo`, `branch`, `self`, Codex rows). Consumers that ignore unknown fields
  keep working.
- Messages are kept in a store under the csq accounts directory and pruned 7 days
  after their last change.
- Artifacts are signed with the same keys shipped clients already trust.
- Messaging ships in both the enterprise (`csq-ee`) and community (`csq`)
  editions.
