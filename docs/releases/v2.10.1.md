**Release date:** 2026-05-23

## What's new

v2.10.1 is a patch release that finishes the per-identity probe correctness work begun in v2.10.0 and lands two doc-codification PRs that capture lessons from that fix.

The single behavioural change: **`csq probe N --provider codex` now reads the slot's own identity-store credentials** (`identities/<UUID>/credentials-codex.json`) instead of the user-global codex-cli state (`~/.codex/auth.json`). Multi-codex-slot installs were structurally incapable of per-slot diagnosis under v2.10.0 — every slot probed against the same user-global file. v2.10.1 fixes the dispatch path so the probe matches the daemon's production credential channel.

If you operate two or more Codex slots and `csq probe` has felt like it returns the same status regardless of which slot you ask about, this is the release that gives you honest per-slot answers.

### What landed

#### `csq probe --provider codex` reads per-identity credentials (an internal ticket / an internal ticket)

Before this release, the codex probe loaded `~/.codex/auth.json` regardless of which slot was being probed — a leftover of the pre-A++ user-global model that survived the per-identity refactor at an internal ticket. The dispatcher now resolves the slot to its UUID via `resolve_slot_to_uuid` and reads `identities/<UUID>/credentials-codex.json` (post-A++ path), falling back to `credentials/codex-<N>.json` only when the `by_slot` mapping is empty (pre-A++ installs).

Spec 11 §11.2 was updated alongside the fix to document the per-identity credential prerequisite as the correct one, replacing the stale `~/.codex/auth.json` mention.

The fix also closed `rules/account-terminal-separation.md` MUST Rule 4 ("Diagnostic Surfaces Read From The Same Credential Channel As Daemon Production Paths") — adopted across `csq doctor` and `csq status` in the same cycle.

#### Codified: fixture-fidelity testing pattern (an internal ticket)

The investigation of an internal ticket surfaced a generalisable testing principle: a unit test for a diagnostic surface MUST stage fixture credentials at every path the surface might read, not just the path the test author had in mind. an internal ticket promotes that finding to a project-wide testing rule and adds it to the `testing-specialist` agent's pre-flight checklist.

#### Docs sweep — daemon/mod.rs subsystem map (an internal ticket)

The daemon module's top-of-file comment still carried v2.7-era "M8 scope" planning narrative (foreground-only, no IPC server yet) — long since superseded by the shipped daemon. The doc was rewritten as a current-state subsystem map (server, refresher, usage_poller, auto_rotate, startup_reconciler, identity_mint, etc.). No runtime change.

### Migration notes

- **No manual migration required.** Upgrading from v2.10.0 is in-place.
- **Behavioural change is narrow:** `csq probe --provider codex` produces correct per-slot results in multi-codex-slot installs. Single-codex-slot installs see no behavioural difference.
- **macOS auto-updater:** the v2.10.0 → v2.10.1 transition is automatic. Developer ID signed + notarized + stapled; minisign signature verifies against the same baked-in pubkey (`F1C2F7FD79F952DD`) used since v2.7.0 — trust chain unchanged.

### What's not yet in v2.10.1

- **RN1-F (terminal `accounts`-field deletion)** — still soak-gated by design (WINDOW-CLOSE N=2). v2.10.1 advances the soak by one cycle.
- **CI-integrated macOS signing**, **Intel Mac auto-update**, **Windows EV cert** — unchanged from v2.10.0 status.
